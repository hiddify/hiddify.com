## راه‌اندازی سرور توسعه { #set-up-a-development-server }

روی یک سرور یا ماشین مجازی لینوکس (ترجیحاً Ubuntu 24.04 یا 26.04) و با کاربر root کار کنید. ماشین توسعه **خودش** یک سرور هیدیفای است: کد همان‌جایی قرار می‌گیرد که هیدیفای نصب‌شده قرار دارد.

```bash
sudo -i
git clone --recurse-submodules -b dev https://github.com/hiddify/Hiddify-Manager.git /opt/hiddify-manager
cd /opt/hiddify-manager
make build
git -C services/panel/src checkout dev
```

`make build` همه‌چیز (MySQL، Redis، HAProxy، Xray، هستهٔ هیدیفای، پنل و …) را همان‌جا نصب می‌کند. بعد پوشهٔ `/opt/hiddify-manager` را در VS Code باز کنید (برای سرور راه دور با افزونهٔ *Remote - SSH*). فایل `.vscode/launch.json` پیکربندی‌های اجرا را دارد.

### کارهای روزمره

- بعد از تغییر کد پایتون پنل، فقط پنل را دوباره راه بیندازید: `systemctl restart hiddify-panel`
- پیکربندی **Admin V2 Dev (Flask + Vite)** در VS Code، پنل را با دیباگر و رابط ادمین را با بارگذاری خودکار اجرا می‌کند.
- بعد از تغییر قالب یا تنظیمات، **الان اعمال کن** را در پنل بزنید یا این را اجرا کنید: `make apply`
- پوشه‌های `data/` (وضعیت سرور) و `generated/` (کانفیگ‌های ساخته‌شده) در گیت نیستند. هیچ‌وقت آن‌ها را ویرایش یا کامیت نکنید.
- تست‌ها در `services/panel/tests` هستند (با pytest). روش اجرا در DEVELOPMENT.md آمده است.

## فرستادن تغییرتان { #send-your-change }

1. در گیت‌هاب از مخزنی که تغییرش داده‌اید **Fork** بگیرید (دکمهٔ بالای صفحهٔ مخزن).
2. از شاخهٔ `dev` یک شاخهٔ جدید بسازید، کامیت کنید و آن را به fork خودتان push کنید. اگر هر دو مخزن را تغییر داده‌اید، اول پنل را کامیت کنید.
3. پیام کامیت را طبق [Conventional Commits](https://www.conventionalcommits.org/) بنویسید، چون changelog از روی آن ساخته می‌شود. مثلاً:

    ```text
    fix: show the right expiry date on the user page
    feat: add a Reality SNI scanner
    ```

4. یک **pull request** به شاخهٔ `dev` مخزن اصلی باز کنید. مشکل، تغییرتان و روش تستش را بنویسید و برای تغییرات ظاهری عکس بگذارید.

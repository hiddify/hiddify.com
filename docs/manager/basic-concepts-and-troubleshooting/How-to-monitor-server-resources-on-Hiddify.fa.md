# کنترل منابع سرور در هیدیفای

در این صفحه یاد می‌گیرید چطور CPU (پردازنده)، RAM (حافظه‌ی کاری) و فضای دیسک سرور را بررسی کنید و اگر یکی از آن‌ها پر شده بود چه کار کنید. وقتی پنل یا اتصال‌ها کند می‌شوند، هنگ می‌کنند یا جواب نمی‌دهند، از این صفحه کمک بگیرید.

## نشانه‌ها

- پنل خیلی کند باز می‌شود یا اصلا باز نمی‌شود.
- اتصال‌ها کند می‌شوند یا قطع می‌شوند، با اینکه آیپی سرور تمیز است.
- نصب یا به‌روزرسانی هیدیفای‌منیجر با خطای کمبود حافظه یا `no space left on device` (فضای دیسک پر است) متوقف می‌شود.

## علت‌های احتمالی

- یک برنامه بیشتر CPU یا RAM را مصرف می‌کند.
- دیسک پر شده است، معمولا به خاطر فایل‌های لاگ بزرگ یا بکاپ‌های قدیمی.

## بررسی ۱: داشبورد پنل

سریع‌ترین راه بررسی است و به هیچ دستوری نیاز ندارد.

1. وارد پنل هیدیفای شوید. اول داشبورد باز می‌شود.
2. کارت وضعیت سرور (که در پنل به آن «نود» می‌گویند) را نگاه کنید. این کارت مصرف CPU هر هسته، RAM، swap، فضای دیسک، بار سیستم (load)، مدت روشن بودن، ترافیک شبکه و تعداد اتصال‌ها را نشان می‌دهد. پرمصرف‌ترین برنامه‌ها و بزرگ‌ترین پوشه‌ها هم در آن فهرست شده‌اند.

![داشبورد هیدیفای](https://user-images.githubusercontent.com/125398461/236671492-9ffc4521-ea2a-4fcb-bfd9-c071ac5a3d4d.png)

!!! note "توجه"
    تصویر بالا مربوط به نسخه‌ی قدیمی پنل است. داشبورد شما ظاهر متفاوتی دارد، ولی همین نوع اطلاعات را نشان می‌دهد.

## بررسی ۲: CPU و RAM با htop

`htop` برنامه‌ای است که به صورت زنده نشان می‌دهد هر برنامه‌ی در حال اجرا (هر **process**) چقدر CPU و RAM مصرف می‌کند.

قبل از شروع، با **SSH** (روشی امن برای وارد کردن دستور روی سرور از راه دور) به سرور وصل شوید. [آموزش اتصال به سرور با SSH](/fa/manager/installation-and-setup/How-to-connect-to-server-via-SSH/) را ببینید. اگر منوی هیدیفای باز شد، `Cancel` (یا کلید `Esc`) را بزنید تا بسته شود. اگر منو هنوز روی صفحه بود، `clear` را تایپ کنید و Enter بزنید.

1. اگر `htop` نصب نیست، آن را نصب کنید. این دستور را روی سرور و از طریق SSH اجرا کنید:

    <div dir=ltr markdown=1>

    ```bash
    apt install htop
    ```

    </div>

    روی اوبونتو معمولا از قبل نصب است.

2. `htop` را باز کنید:

    <div dir="ltr" markdown=1>

    ```bash
    htop
    ```

    </div>

    ![نمایش برنامه‌ها در htop](https://github.com/hiddify/hiddify-config/assets/125398461/38c5ab1f-8fed-49c9-9455-04c7a7e83917)

3. برای مرتب کردن برنامه‌ها بر اساس مصرف CPU، روی عنوان ستون `CPU%` کلیک کنید. برنامه‌ای که بالای فهرست است بیشترین CPU را مصرف می‌کند.
4. برای مرتب کردن بر اساس مصرف RAM، روی عنوان ستون `MEM%` کلیک کنید.
5. برای خروج از `htop` کلید `q` (یا `Ctrl+C`) را بزنید.

## راه حل

### یکی از سرویس‌های هیدیفای CPU یا RAM زیادی مصرف می‌کند

نام سرویس‌های هیدیفای با `hiddify-` شروع می‌شود، مثل `hiddify-panel`، `hiddify-xray`، `hiddify-core` و `hiddify-haproxy`. آموزش‌های قدیمی از `hiddify-nginx` و `hiddify-singbox` نام می‌برند: nginx در نسخه‌ی ۱۴ حذف شده و `hiddify-singbox` حالا `hiddify-core` نام دارد.

اگر یکی از این سرویس‌ها بیشتر CPU یا RAM را مصرف می‌کند، سرویس‌ها را ری‌استارت کنید. این دستور را روی سرور و از طریق SSH اجرا کنید:

<div dir=ltr markdown=1>

```bash
hiddify restart
```

</div>

همچنین می‌توانید `hiddify` را بدون هیچ گزینه‌ای اجرا کنید تا منوی هیدیفای باز شود، و با کلیدهای جهت‌دار گزینه‌ی `restart` را انتخاب کنید. [آموزش اتصال و عیب‌یابی با SSH](/fa/manager/configuration-and-advanced-settings/How-to-connect-and-troubleshoot-via-SSH/) را ببینید.

بعد از تمام شدن ری‌استارت، بررسی کنید که همه‌ی سرویس‌ها در حال اجرا باشند:

<div dir=ltr markdown=1>

```bash
hiddify status
```

</div>

سپس دوباره `htop` را باز کنید و ببینید مصرف کم شده یا نه. اگر خیلی زود دوباره بالا رفت، در [گروه تلگرام هیدیفای](https://t.me/hiddify_board) کمک بخواهید.

### رم پر به نظر می‌رسد

RAM حافظه‌ی موقتی است که برنامه‌های در حال اجرا و خود سیستم عامل از آن استفاده می‌کنند. چند نکته که به شما کمک می‌کند عددها را درست بخوانید:

- مقدار رم مصرفی رابطه‌ی مستقیمی با تعداد کاربران ندارد. سرویس‌های هیدیفای و سیستم عامل، چه ۱۰ کاربر داشته باشید چه ۱۰۰۰ کاربر، به حافظه نیاز دارند.
- لینوکس از رم خالی به عنوان **کش** (نسخه‌ی موقت فایل‌ها برای سریع‌تر شدن کارها) استفاده می‌کند. پس پر بودن رم تا حدود ۸۰٪ کاملا طبیعی است و لازم نیست کاری بکنید.
- فقط به خاطر پر بودن رم، سرور را ریبوت نکنید.

اگر باز هم می‌خواهید کش را خالی کنید، این دستور را با کاربر `root`، روی سرور و از طریق SSH اجرا کنید:

<div dir=ltr markdown=1>

```bash
sync && sysctl -w vm.drop_caches=3
```

</div>

اگر این دستور خطا داد، از دستور زیر استفاده کنید. این دستور مقدار حافظه‌ی آزاد را قبل و بعد از خالی کردن کش هم نشان می‌دهد:

<div dir=ltr markdown=1>

```bash
free && sync && echo 3 > /proc/sys/vm/drop_caches && free
```

</div>

اگر رم سرور خیلی کم است، اضافه کردن swap (فضایی از دیسک که به جای حافظه‌ی اضافه استفاده می‌شود) کمک می‌کند. [آموزش فعال کردن Swap در لینوکس](/fa/manager/basic-concepts-and-troubleshooting/How-to-enable-Swap-on-Linux/) را ببینید.

### دیسک پر شده است

1. فضای دیسک را بررسی کنید. این دستور را روی سرور و از طریق SSH اجرا کنید:

    <div dir=ltr markdown=1>

    ```bash
    df -h --total
    ```

    </div>

    باید جدولی مثل این ببینید:

    <div align=center markdown=1>

    ![خروجی دستور df](https://github.com/hiddify/hiddify-config/assets/125398461/f3552ab5-a105-40b5-8210-65487903c6ba)
    </div>

2. ردیف دیسک اصلی (دیسکی که روی `/` قرار دارد و معمولا `sda1` یا `vda1` نام دارد) را نگاه کنید. اگر `Use%` نزدیک ۱۰۰٪ است، باید مقداری فضا آزاد کنید.
3. هیدیفای لاگ‌هایش را در `/opt/hiddify-manager/data/log` نگه می‌دارد (نسخه‌های قدیمی از `/opt/hiddify-manager/log/system` استفاده می‌کردند که دیگر وجود ندارد). برای خالی کردن همه‌ی فایل‌های لاگ، بدون اینکه سرویس‌هایی که در آن‌ها می‌نویسند به مشکل بخورند:

    <div dir=ltr markdown=1>

    ```bash
    find /opt/hiddify-manager/data/log -type f -name "*.log" -exec truncate -s 0 {} +
    ```

    </div>

    از نسخه‌ی ۱۴، هیدیفای حجم لاگ‌های خودش را محدود می‌کند (هر فایل لاگ وقتی از ۱۰۰ مگابایت بزرگ‌تر شود خالی می‌شود و حجم ژورنال سیستم حداکثر ۵۰۰ مگابایت است)، پس لاگ‌ها به‌ندرت به تنهایی دیسک را پر می‌کنند.

4. هیدیفای بکاپ‌های خودکار را هم در `/opt/hiddify-manager/data/backup` نگه می‌دارد. اگر این پوشه بزرگ است، بکاپ‌هایی را که می‌خواهید نگه دارید دانلود کنید و بعد بکاپ‌های قدیمی را پاک کنید. بقیه‌ی پوشه‌ی `/opt/hiddify-manager/data` را پاک نکنید: دیتابیس و تنظیمات شما در آن است.
5. دوباره `df -h --total` را اجرا کنید و مطمئن شوید فضا آزاد شده است.

</div>

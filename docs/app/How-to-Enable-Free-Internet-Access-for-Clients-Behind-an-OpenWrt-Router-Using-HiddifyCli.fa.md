# اینترنت آزاد برای همهٔ دستگاه‌های پشت روتر OpenWrt

با هستهٔ هیدیفای روی روتر OpenWrt، همهٔ گوشی‌ها، لپ‌تاپ‌ها، تلویزیون‌ها و کنسول‌های بازی خانه می‌توانند از پروکسی شما استفاده کنند، بدون این‌که روی خودشان چیزی نصب کنید. این صفحه روشش را توضیح می‌دهد.

!!! note "نوشته‌شده برای هستهٔ هیدیفای نسخهٔ 5.9"
    این صفحه برای هستهٔ هیدیفای نسخهٔ **5.9** (5.9.3) است. نسخه‌های قدیمی این راهنما این کار را دستی با `redsocks` و قوانین `iptables` انجام می‌دادند. دیگر لازم نیست: بستهٔ هستهٔ هیدیفای یک **حالت روتر** دارد که همین کار را می‌کند، و دستورهای قدیمی `iptables` روی OpenWrt 22.03 و جدیدتر که از nftables استفاده می‌کنند کار نمی‌کنند.

## پیش از شروع

هستهٔ هیدیفای را روی روتر نصب کنید و لینک اتصال را به آن بدهید: قدم‌های ۱ و ۲ [هستهٔ هیدیفای روی OpenWrt](How-to-use-HiddifyCli-on-OpenWrt.md) را انجام دهید.

## حالت روتر (پیش‌فرض)

بستهٔ هستهٔ هیدیفای در **حالت روتر** شروع به کار می‌کند. در این حالت:

- همهٔ دستگاه‌های پشت روتر، برای TCP، UDP و پینگ، از پروکسی عبور می‌کنند؛
- روی دستگاه‌ها لازم نیست چیزی تنظیم کنید و مثل همیشه از روتر استفاده می‌کنند؛
- اتصال‌هایی که از بیرون می‌آیند هنوز به روتر و پورت‌فورواردهایش می‌رسند.

برای بررسی، یک گوشی یا کامپیوتر را با وای‌فای یا کابل به روتر وصل کنید و سایتی را باز کنید که آی‌پی شما را نشان می‌دهد. باید آی‌پی سرور پروکسی را نشان دهد.

اگر حالت روتر خاموش شده بود، دوباره روشنش کنید:

```bash
uci set hiddify-core.main.mode='router'
uci commit hiddify-core
/etc/init.d/hiddify-core restart
```

## اگر کار نکرد

- لاگ را ببینید: `logread -e hiddify-core`. خطاهای مربوط به کانفیگ یا سابسکریپشن یعنی لینک قدم ۲ اشتباه است یا دانلود نمی‌شود.
- بررسی کنید سرویس در حال اجراست: `/etc/init.d/hiddify-core status`.
- دوباره راهش بیندازید: `/etc/init.d/hiddify-core restart`.
- اگر فقط خود روتر باید از پروکسی استفاده کند، به‌جای آن حالت پروکسی را بگذارید (`option mode 'proxy'`): در این حالت پروکسی فقط روی خود روتر و روی `127.0.0.1:12334` اجرا می‌شود. بخش [حالت روتر و حالت پروکسی](How-to-use-HiddifyCli-on-OpenWrt.md#router-mode-and-proxy-mode) را ببینید.

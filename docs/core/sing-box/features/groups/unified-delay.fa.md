# تأخیر یکسان (Unified delay)

[همهٔ قابلیت‌های هیدیفای](../../index.md)

با تأخیر یکسان، تست URL زمان یک رفت‌وبرگشت HTTP را روی اتصالی که از قبل باز است اندازه می‌گیرد،
نه زمان باز کردن اتصال و گرفتن اولین پاسخ را. این یک کلید در بخش `experimental` است:
`"unified_delay": {"enabled": true}`.

## چرا از آن استفاده کنیم

تست URL معمولی دست‌دادن‌ها را هم حساب می‌کند: TCP، پروتکل پراکسی و TLS با سایت تست. پروتکل‌هایی
که دست‌دادن طولانی‌تری دارند کندتر به نظر می‌رسند، حتی وقتی ترافیک را به همان سرعت می‌برند، و
عددها با هزینهٔ هر اتصال تازه بالا و پایین می‌شوند.

با تأخیر یکسان، همهٔ خروجی‌ها به یک شکل و روی اتصال باز اندازه گرفته می‌شوند. عددها کمتر،
پایدارتر و برای مقایسهٔ پروتکل‌ها ساده‌تر هستند. وقتی زمان باز کردن اتصال تازه برایتان مهم است،
مثلاً برای اتصال‌های کوتاه و زیاد، آن را خاموش کنید.

## چطور از فیلترینگ عبور می‌کند

عبور نمی‌دهد. فقط روش اندازه‌گیری تأخیر را تغییر می‌دهد.

## چطور کار می‌کند

- تست مثل همیشه اتصال را باز می‌کند و درخواست HEAD خود را می‌فرستد.
- پس از پاسخ، همان درخواست را دوباره روی همان اتصال می‌فرستد و فقط زمان این درخواست دوم را گزارش
  می‌کند.
- اگر هر کدام از دو درخواست ناموفق شود، تست ناموفق است.
- روی همهٔ تست‌های URL که sing-box اجرا می‌کند اثر دارد: گروه‌های URL test،
  [پایش](monitoring.md) (و همراه آن [متعادل‌کننده](balancer.md)) و تست‌هایی که برنامه
  درخواست می‌کند. تست تأخیر Clash API تغییری نمی‌کند.

## پیکربندی

```json
{
  "experimental": {
    "unified_delay": {
      "enabled": true
    }
  }
}
```

| فیلد | نوع | پیش‌فرض | معنی |
|---|---|---|---|
| `unified_delay.enabled` | bool | `false` | زمان درخواست دوم روی اتصال باز را گزارش کن. |

سایت تست باید پس از پاسخ اول اتصال را باز نگه دارد. نشانی‌های رایج تست مثل
`https://www.gstatic.com/generate_204` این کار را می‌کنند.

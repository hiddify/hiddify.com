# جایگزین (Fallback)

[همهٔ قابلیت‌های هیدیفای](../../index.md)

گروه جایگزین اعضایش را به ترتیب امتحان می‌کند و از اولین عضوی که وصل شود استفاده می‌کند.
عضوی که ناموفق باشد مدتی کنار گذاشته می‌شود تا یک سرور مرده همهٔ اتصال‌ها را کند نکند. این یک
outbound است: `"type": "fallback"` در فهرست `outbounds`.

## چرا از آن استفاده کنیم

- یک سرور اصلی و یک یا چند سرور پشتیبان دارید و می‌خواهید پشتیبان فقط وقتی اصلی خراب است به
  کار برود.
- می‌خواهید جابه‌جایی همان لحظه‌ای رخ دهد که اتصال ناموفق می‌شود، نه پس از تست URL بعدی.

فقط ناموفق بودن باز کردن اتصال را می‌بیند. بعضی خروجی‌ها اتصال را پیش از پاسخ سرور باز
گزارش می‌کنند و بعداً خطا می‌دهند. این خطاها دیده نمی‌شوند: برای آن‌ها از
[متعادل‌کننده](balancer.md) یا گروه URL test استفاده کنید که خود سرور را تست می‌کنند.

## چطور از فیلترینگ عبور می‌کند

خودش عبور نمی‌دهد. فقط میان خروجی‌هایی انتخاب می‌کند که این کار را می‌کنند.

## چطور کار می‌کند

- برای هر اتصال، گروه اعضا را به ترتیب پیکربندی امتحان می‌کند و از اولین عضوی که اتصال را
  باز کند استفاده می‌کند. برای TCP و UDP یکسان کار می‌کند.
- عضوی که ناموفق باشد به مدت `blacklist_timeout` کنار گذاشته می‌شود. به انتهای ترتیب می‌رود و
  فقط وقتی امتحان می‌شود که بقیه همه ناموفق باشند. پس عضو مرده در هر بازهٔ timeout یک تلاش
  ناموفق هزینه دارد، نه در هر اتصال.
- وقتی عضوی اتصالی را باز کند، از فهرست کنارگذاشته‌ها بیرون می‌آید.
- اگر اتصال هنگام تلاش یک عضو لغو شود، گروه متوقف می‌شود و عضو بعدی را امتحان نمی‌کند.
- اگر همهٔ اعضا ناموفق باشند، اتصال با خطای هر عضو ناموفق می‌شود.
- گروه عضوی را که آخرین بار اتصالی باز کرده، به‌عنوان انتخاب فعلی‌اش گزارش می‌کند.

## پیکربندی

```json
{
  "type": "fallback",
  "tag": "fallback",
  "outbounds": ["main", "backup"],
  "blacklist_timeout": "1m"
}
```

| فیلد | نوع | پیش‌فرض | معنی |
|---|---|---|---|
| `outbounds` | list of strings | الزامی | تگ اعضا، به ترتیبی که امتحان می‌شوند. |
| `blacklist_timeout` | duration | `1m` | مدتی که عضو ناموفق کنار گذاشته می‌شود. |

از sing-box-extended منتقل شده است.

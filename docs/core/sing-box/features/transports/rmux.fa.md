# چندگانه‌سازی rmux

[همهٔ قابلیت‌های هیدیفای](../../index.md)

rmux یک پروتکل دیگر برای چندگانه‌سازی (multiplex) در sing-box است: `"multiplex": {"protocol": "rmux"}`
در یک outbound. مثل `smux`، `yamux` و `h2mux`، چندین اتصال را درون یک اتصال به سرور حمل می‌کند. از
sing-box-extended ‏(github.com/shtorm-7/rmux) آمده است.

## چرا از آن استفاده کنیم

- اتصال‌های کمتر به سرور: هر اتصال تازه یک جریان در نشستی که از قبل هست باز می‌کند، بدون دست‌دادن
  تازه، پس زودتر شروع می‌شود و شبکه اتصال‌های کمتری می‌بیند.
- چندگانه‌سازی غیر از موارد رایج می‌خواهید؛ rmux تازه‌تر است و روی شبکه کمتر دیده می‌شود.

## چطور از فیلترینگ عبور می‌کند

به‌تنهایی عبور نمی‌کند. درون پروتکل و ترابری outbound اجرا می‌شود و شبکه همان‌ها را می‌بیند.

## چطور کار می‌کند

- داده در قاب‌هایی حداکثر ۳۲ کیلوبایتی می‌رود که هر کدام برچسب جریانش را دارد.
- مثل `h2mux`، می‌توان نوشتن یک جریان را بست در حالی که هنوز می‌خواند.
- نشست‌ها مثل پروتکل‌های دیگر نگه داشته و دوباره استفاده می‌شوند؛ قاب‌های keepalive خاموش‌اند، چون
  خود sing-box نشست‌های بیکار را مدیریت می‌کند.

## پیکربندی

```json
{
  "type": "vless",
  "server": "example.com",
  "server_port": 443,
  "uuid": "b831381d-6324-4d53-ad4f-8cda48b30811",
  "multiplex": { "enabled": true, "protocol": "rmux", "max_connections": 4 }
}
```

inbound سرور به `"multiplex": {"enabled": true}` و sing-box هیدیفای نیاز دارد: rmux را مثل
پروتکل‌های دیگر می‌پذیرد، ولی سرور sing-box اصلی آن را رد می‌کند. بقیهٔ فیلدهای `multiplex` مثل
پروتکل‌های دیگر کار می‌کنند. برچسب ساخت لازم نیست.
